RAG Course — my notes 📓

key concepts + interview prep, in my own words

1. Level 1 — the basics

RAG

= Retrieval-Augmented Generation. Basically: let the AI read my docs before it answers, instead of just guessing from training data.

  • Embeddings — turn text into numbers so AI can compare meaning, not just words
  • Vector store — a database that holds those numbers, searchable fast
  • Chunking — cut big docs into small pieces (the model can't read forever!)
  • Similarity search = semantic search → find the closest-meaning chunks
  • Prompt — the instruction I give the model
  • LLM — the "brain" (GPT etc.)
  • Context window — how much it can read at once ⚠ has a hard limit

2. Level 2 — intermediate

Tool calling → model picks + uses outside functions on its own (calculator, DB lookup, search…)

Router query engine → decides HOW to search depending on the question type

Agent → plans, uses tools, thinks step by step (not one-shot!)

ReAct loop → Reason → Act → Observe → repeat

Summary index = reads ALL chunks  |  Vector index = only top matches

Multi-doc RAG → search across many documents at once

3. Level 3 — advanced (the impressive stuff)

  • Chunk size tuning — too big = slow + wastes context, too small = loses meaning
  • Chunk overlap — repeat a bit of prev. chunk so meaning at the edges isn't lost
  • Re-ranking — after search, re-sort results by actual relevance (cross-encoder)
  • Hallucination — AI makes stuff up instead of using my docs ← big interview topic!
  • Guardrails — rules that stop bad/wrong answers
  • Fine-tuning — actually retrain the model on my data
  • Self-RAG — model double-checks its own answer against retrieved docs
chunk = 512–1024 tokens typical overlap ≈ 50–100 tokens

4. The full pipeline (Q5 answer, memorize this!)

3 stages

① Ingestion — load docs → chunk → embed → store in vector DB

② Retrieval — question → embed it → search DB → get top-K chunks

③ Generation — feed chunks + question to LLM → answer grounded in context

5. Interview Q&A — quick answers

Q: Simple RAG vs Agent?

Simple RAG = search → context → answer (one shot).
Agent = think → pick tool → act → observe → think again... loops till done. Can use multiple tools + multiple searches.

Q: Keyword vs semantic search?

Keyword = exact word match only. Semantic = matches by meaning ("ML" ≈ "machine learning"). Best practice → hybrid search (both together).

Q: How to stop hallucinations?
  • tell model "only answer from context"
  • Self-RAG — check answer vs retrieved docs
  • force citations to source chunk
  • re-rank so best chunks are used
  • temperature = 0 for factual answers
Q: Choosing chunk size?

Small (256–512) → precise Q&A. Large (1024–2048) → summaries, more context kept. Add overlap so boundary info isn't lost. Honestly — just test on real data.

Q: Build RAG for 10,000 company docs — how?
  • ingest w/ good chunking
  • scalable vector DB (Pinecone / Weaviate)
  • metadata filters — date, dept, doc type
  • router for different query types
  • multi-doc agents for cross-doc Qs
  • re-ranking for quality
  • monitor + eval w/ user feedback
